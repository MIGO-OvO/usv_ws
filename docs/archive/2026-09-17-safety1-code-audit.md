# safety1 提交前代码审计

审计范围：上一轮尚未提交的五端代码、测试、根文档与版本检查器。
流程：三个并行只读审计方向 + 主代理 Web/发布审计；确定性复现后修正、复测，再按仓库提交。
使用诊断技能保证新增问题有红→绿证据；未连接真实硬件、未刷写、未推送远端。

## 已发现并修正的问题

| 范围 | 已复现问题 | 修正方向 |
|---|---|---|
| ROS 终态 | 旧 finished 可释放新 FCU ID；快速终态早于启动 ACK 被丢弃 | attempt/source/sample_id 关联，提前终态缓存，拒绝启动优先 |
| 控制清理 | 停止/进样关闭失败仍可能报告成功或 SKIP | 关停失败强制失败，不允许放行 |
| ROS 兼容入口 | 旧分光话题/服务绕过运行/故障互锁 | 统一控制锁与入口门禁；旧线程退出前不能重载上下文 |
| 走航 | STOP 后采样循环可能启动下一轮 | 取消整个调度，覆盖运行、间隔与启动检查交错 |
| 人工接管 | 迟到 USV_FAIL/ROS HOLD 覆盖 MANUAL/RTL | 当前 AUTO + 当前采样匹配；人工接管优先 |
| 非 USV 脚本 | guided.enter 失败继承旧 command1，误判超时 | 在进入检查前刷新 command，保留原有失败完成语义 |
| Web 急停 | 两个急停入口和 raw STOP 未使待确认启动失效 | 统一取消 generation，原子提交 owner，重复发送必要的停止 |
| Web 记录 | 旧/无 ID 终态关闭新窗口，停止新 owner 续约 | 关联窗口 attempt，匹配早到终态在窗口建立后消费 |
| Web 并发 | A 收尾清理可关闭并清空刚建立的 B | 生命周期锁保护完整清理与新窗口准备；网络启动 RPC 不持该锁 |
| Web 回滚 | 已有 survey/lab 文件时拒绝启动残留空窗口 | 分别回滚本次窗口/本次新建文件，保留原记录 |
| Windows 关闭 | 写失败时优化器 stop 回调递归 close_serial | 关闭防重入，清理期间禁止回调发送，异常不阻断端口释放 |
| PID 测试 | 2 秒阻塞轮间等待延迟看门狗并可先启动下一轮 | 非阻塞等待；超时/停止撤销待启动轮次 |
| 分光数据 | bit4 虽标无效，仍可进入真实参考和吸光度缓冲 | 真实有效帧才参与参考/信号统计，原始诊断保留质量标记 |
| 版本清单 | 同提交 CRLF/LF 检出得到不同源码哈希 | schema v2 采用文本 LF 规范化；旧 v1 清单保留作历史记录 |

旧任务清理 RPC 的请求/响应延迟也已用真实引擎与模拟串口复现并修复：新增按 attempt 原子校验的 `automation_cleanup`，旧 owner 不触碰新 owner；预启动进样绑定归属，已有会话故障不能被一次成功写停止命令转换成成功采样。人工 QGC 31011 无本地上下文时仍能全局停止 Web 任务。走航间隔的进样 owner 保持续约，失联会停泵。

所有权回归 11 项、终态回归 16 项、Web 生命周期回归 10 项通过；包括请求/响应延迟、提前终态、错误归属、清理故障、全局停止和窗口交错。

## 验证边界

- ESP32、SITL 构建与纯模拟串口/ROS 测试不等于机械、电台、Jetson 或实船验收。
- `USV_DONE/USV_FAIL` 尚无持久化端到端 ACK 或跨飞控重启会话保证。
- HTTP 令牌仅保护 Web 写入口；ROS 图与 MAVLink 链路仍需可信网络/网络隔离。component ID 过滤不是加密身份认证。
- 原有两项地图断言与旧测试告警保持记录，不通过削弱断言伪造全量通过。
- 当前本地分支均为 `codex/safety1-audit`；根 `.ai-bridge`、`.impeccable`、`PRODUCT.md`，ROS `.ai-bridge`、QGC `.workbuddy` 不在提交范围。

提交不代表批准部署；仍需维护者完成独立台架/实船验收。
